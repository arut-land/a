# Requested side metadata

PROTO 42 removes the core's special handling of a plugin purpose. The thin
history index keeps generic latest-completed coordinates (ordinal and revision),
never completed side text. A connection declares the purposes it wants; its
public heads include only those references. The SDK requests their values through
the existing history lane and immutable weak page cache, independently of the
presentation window. Replacements retain the previous value until delivery;
new generations cancel old requests and discard old metadata. Blank completed
values preserve the last usable coordinates, matching `SessionView::side`.

The UI chooses its label purpose. Protocol, kernel and engine do not name it.
TUI and web consume metadata updates; FFI exposes them through the existing
activity update and header fields, which Swift already consumes. Browser DOM
retention, find, selection, copy and accessibility behavior are unchanged.

## Attach comparison

Measured 2026-10-30 on the shared Apple M3 arm64, 16 GiB, macOS 27.0.1.
Release fixtures builds, `CARGO_BUILD_JOBS=2`, one external target directory.
The baseline is `17879779ef0e5fe2e4e8fdf962bcccb8c6328847`: Stage B before this
metadata fix, merged with main's `7c6a48fb` mailbox change. Candidate code is
`1262c28c`. Both sides therefore include the mailbox change. Artifact hashes,
source revisions and every observation are in
[history-paging-metadata.json](history-paging-metadata.json).

Three fresh daemon pairs alternate A/B, B/A, A/B. Each home is copied from the
same typed `Jsonl::import` seed: 32 assistant items of 128 KiB, a completed
23-byte label, and a completed 6 MiB unrequested side result. Each arm attaches
cold requesting the label, warm requesting it, then warm without metadata.
The real SDK has no presentation demand. Timing starts after the hello, before
Attach; controls finish at `Synced`, and requested metadata finishes when its
page is installed. Head bytes count complete encoded Head/HeadPart frames,
excluding requested page frames and other handshake/control messages.

Provider variables are removed after `mise exec`; the endpoint is loopback and
the credential is a dummy. The workload makes no model requests. Every owned
daemon is stopped with its matching isolated `A_HOME` before its home is removed.

Times are median [min, max], milliseconds; n=3 per cell.

| Cold, requested | 33.392 [33.145, 33.713] | 35.966 [34.884, 36.890] | 33.394 [33.147, 33.715] | 36.143 [35.071, 37.102] |
| Warm, requested | 0.096 [0.083, 0.104] | 0.114 [0.112, 0.117] | 0.097 [0.085, 0.105] | 0.246 [0.235, 0.253] |
| Warm, unrequested | 0.090 [0.085, 0.091] | 0.081 [0.081, 0.094] | — | — |

| Head/demand condition | Before | After |
| --- | ---: | ---: |
| Requested head bytes | 433 [433, 433] | 444 [444, 444] |
| Unrequested head bytes | 433 [433, 433] | 410 [410, 410] |
| Additional requested history ranges | 0 | 1 |
| Additional unrequested history ranges | 0 | 0 |
| Label present without a declaration | yes | no |

This is an architecture correction, with an attach cost: requested metadata adds
one range round trip. In these samples cold control delivery increases 2.574 ms;
warm label readiness increases 0.149 ms. Requested heads gain 11 bytes for
coordinates, while unrequested heads lose 23 bytes. Controls do not depend on
metadata-page completion. The test also asserts that the 6 MiB unrequested side
payload never reaches a head or the SDK's retained metadata, and the presentation
window stays empty. Three pairs on a shared host establish the observed spread,
not a general latency bound.

Only attach latency and control-head bytes were remeasured. The prior deep-session,
large-echo, renderer-memory, allocator and encoder-CPU measurements in
[history-paging.md](history-paging.md) remain pinned to their original artifacts;
this follow-up does not claim new results for those workloads.

## Invariants and verification

The real index, SDK, socket server and FFI tests cover arbitrary purposes,
unrequested-payload exclusion, sharing/releasing immutable pages, retaining old
values during replacement, generation cancellation, blank results, live changes
to declarations and labels outside the presentation window. The architecture
invariant `no_plugin_is_named_below_the_plugin_layer` passes. PROTO 42's corpus
was generated with `UPDATE_WIRE=1 cargo test -p protocol --test wire`; view
vectors were regenerated by their `UPDATE_VECTORS=1` test and were unchanged.

On the merged code: 2,280 workspace tests pass (`--features a/lua`), touched-crate
clippy with all targets/features and `-D warnings` passes, docs pass with warnings
denied, and `mise run check:windows` passes. The native Swift suite passes, plus
a live FFI/Swift check attaches to the typed seed and observes the label while
its transcript item is outside the native presentation window. All builds and
Swift scratch/generated outputs stay under the single external target directory.

## Windows timeout investigation

CI [40979057260](https://github.com/arut-land/a/actions/runs/40979057260) failed
the architecture invariant and two Windows x64 engine tests:

- `tests::inheritance::session_and_fast_roles_use_kind_seeded_settings`
- `tests::inherited_task_cannot_reset_an_exhausted_depth_budget`

Both panic at the existing 10-second `Daemon::wait` assertion, `never settled`;
they are not nextest's outer slow-test termination. No deadline was increased.
The depth-budget failure is proven on literal main at
[40668200919, job 122748677107](https://github.com/arut-land/a/actions/runs/40668200919/job/122748677107)
(`6af617cc`, October 28, same assertion, 16.709 s including teardown), and
[40113179623, job 120929199144](https://github.com/arut-land/a/actions/runs/40113179623/job/120929199144)
(`e98c09c6`, October 24, same assertion, 16.390 s).

The audit examined 120 main runs plus 62 runs at merged main-ancestor SHAs,
including available failed/cancelled Windows logs and 132 failed/cancelled
check/regression logs. Some cancelled-job logs return 404. It found no prior
failure of the role-settings test; a failure on main is therefore **not proven**.
Both tests pass 100 stress iterations on main `ea0ce5ff` and 100 on this branch.
A further four-process interleaved comparison executes each test 200 times per
revision: 800 executions, zero failures. These are debug correctness/stress runs,
not release performance samples, and they do not reproduce the hosted Windows
runtime. The final merged workspace run also passes both tests.

The role-settings timeout remains unexplained. The tests attach directly to the
engine, without a public outbox; the requested metadata/index path is not used.
The internal `FrameLog::batches_after`/store batch reader is unchanged from main.
This narrows the changed paths but does not prove a root cause or exclude a
timing-sensitive regression. No guessed scheduling/locking fix was added.
Owner-pending if it recurs: capture actor/flush/child progress on native Windows;
likelihood is unquantified (one observed branch CI failure, no local reproduction);
cost is native diagnostic instrumentation and another controlled hosted run.
